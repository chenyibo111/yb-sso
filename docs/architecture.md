# 飞书企业成员单点登录设计

## 目标

由已有飞书测试企业负责成员身份认证；独立的 Go 登录中心为多个本地项目提供统一的 OIDC 登录入口。第一阶段只服务一个飞书企业及其可用范围内的成员。

## 方案

业务项目不直接连接飞书。项目发现未登录时跳转到 Go 登录中心；登录中心将用户送往飞书授权页，收到回调后在服务端换取身份信息，校验企业成员资格，查找或建立内部用户映射，再完成面向业务项目的 OIDC 授权码流程。项目使用内部用户 ID（OIDC `sub`）识别成员。

这种双层结构让新增业务项目只需接入 OIDC，不需重复处理飞书协议或飞书应用凭证。与“每个项目直接对接飞书”相比，中心服务需要自行管理客户端、签名密钥、会话和退出行为；这是实现可复用 SSO 的核心工作。

## 数据边界

- 内部用户 ID 由 SSO 生成且保持稳定；飞书 `open_id` 只作为该飞书应用中的外部身份键，不直接用作业务项目的用户主键。
- 飞书企业和应用可用范围限定谁可以登录。登录中心在认证时再次确认成员状态，并为会话设置有限有效期；成员离职或失去权限后需要有明确的会话失效策略。
- 各业务项目各自管理业务权限；SSO 第一阶段只表达身份及基础成员状态。
- App Secret、OIDC 签名私钥和数据库密码不写入仓库。回调地址必须精确登记；授权码流程使用 PKCE。

## 非目标

第一阶段不实现本地密码、公开注册、多企业租户、自动同步飞书通讯录、互联网部署或自制密码学协议。

## 实施前置条件

- 在飞书测试企业创建企业自建应用，配置两名成员可使用及登录回调地址。
- 在开发机器安装 Go；当前环境执行 `go version` 未找到 Go 命令。
- 确定本地回调地址能通过飞书开发者后台校验。若不能，使用临时 HTTPS 隧道，仅供开发联调。
