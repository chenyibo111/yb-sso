# 企业成员校验与跨项目退出设计

## 目的

现有本地 MVP 已由两名飞书测试企业成员验证：成员能登录项目 A、B；同一成员在两项目得到相同的 `sub`，不同成员得到不同的 `sub`。下一阶段要在登录时显式核对企业身份，并让用户从任一项目退出后，两个项目及 Hydra SSO 会话都失效。

## 已确认的选择

- 飞书仍是唯一登录方式，企业自建应用仍只服务一个测试企业。
- 从项目 A 或 B 退出时，同一浏览器中的两个项目与 SSO 会话都应失效。
- 以 Hydra 的 OIDC 后端退出通知为主要集成方式，供未来项目按标准接入。

## 比较过的方案

1. **仅用 OIDC 后端退出通知。** 接入方式标准，未来项目可复用；但 Hydra 2.3 异步发送通知，通知延迟或失败时，其他项目可能暂时保留本地会话，无法满足“退出完成后立即失效”。
2. **仅用共享会话表。** 每个项目每次访问受保护资源时查询中央状态，结果明确；所有项目必须实现本平台的额外接口，不能单靠 OIDC 标准集成。
3. **OIDC 后端退出通知，加受保护请求时的撤销状态校验。** 保留标准退出通知；项目在实际提供受保护内容前再核对会话状态。此方案满足本地演示的即时失效要求，代价是每次受保护请求增加一次本机 SSO 查询。选用此方案。

## 登录与企业边界

- `.env` 增加必填 `FEISHU_TENANT_KEY`。Go 登录服务取得飞书 `user_info` 后，要求 `open_id` 和 `tenant_key` 都非空，且 `tenant_key` 与配置完全相同；不匹配或缺失时拒绝 Hydra 登录挑战。
- 保留飞书企业自建应用的企业归属和应用可用范围作为第一层限制。这里的 `tenant_key` 比对是第二层限制，不把邮箱或姓名当成员身份凭据。
- `sub` 生成规则保持不变，已有两个成员的内部 ID 不迁移。
- 真实飞书联调若发现当前 v1 `user_info` 不返回 `tenant_key`，服务保持拒绝；先核实飞书官方可用的成员接口，再调整实现，不静默跳过检查。
- 本阶段不实现通讯录事件订阅，也不承诺成员移出企业后已发出的所有令牌立即失效；新登录必须重新经过飞书。

## 退出流程

1. 演示项目保存经验证的原始 ID Token 及其中的 `sid`，项目的“退出”入口跳转 Hydra 发现文档中的 `end_session_endpoint`，携带 `id_token_hint` 和已登记的 `post_logout_redirect_uri`。
2. Hydra 将 `logout_challenge` 交给 Go 登录服务。服务从 Hydra 管理 API 读取挑战，得到 `subject` 和 `sid`；没有有效 `sid` 的请求拒绝处理。
3. Go 服务把 `sid` 写入 PostgreSQL 的撤销表，再接受退出挑战。数据库写入失败时不确认退出，向用户显示可重试的错误。
4. 浏览器回到 Hydra 完成会话清除。Hydra 异步向登记的项目 A、B 发送 OIDC 后端退出令牌。项目验证令牌签名、发行者、受众、事件类型、时间和 `sid` 后删除对应本地会话。
5. 项目 A、B 在每次返回受保护页面前，也把其 ID Token 交给本机 Go 登录服务查询该 `sid` 是否被撤销。查询失败时拒绝提供页面；因此即使异步通知尚未到达，下一次访问也不会继续使用已撤销的会话。
6. 退出成功页只显示退出结果和重新登录入口，不自动启动新授权请求。重新登录会重新经过 Hydra 与飞书。

## 本地运行方式

- Hydra、PostgreSQL、项目 A、项目 B 都由 Docker Compose 管理。两个演示项目通过 Compose 内部网络接收 Hydra 的后端通知；浏览器仍使用 `localhost:3100` 和 `localhost:3101`。
- Go 登录服务保留本机 `localhost:9000`。PostgreSQL 仅在本机回环地址发布开发端口供 Go 服务连接；Hydra 管理端口继续只绑定本机。
- 客户端登记脚本为两个演示客户端增加后端退出地址和退出后的回调地址，重复运行可安全更新这两个由项目创建的客户端。
- 本地内存会话在进程重启时丢失；撤销记录在 PostgreSQL 持久化。后续部署多实例时需重新审视此实现的会话存储和健康策略。

## 验证

- 单元测试覆盖 `tenant_key` 缺失或不匹配、有效成员、退出挑战无 `sid`、数据库写入失败、伪造或错误受众的退出令牌、撤销后的受保护请求。
- 本地联调覆盖：成员登录 A/B；从 A 退出后访问 A/B 均需重新登录；从 B 退出同样成立；另一名成员的会话不受影响；Hydra 登录会话不自动复用。
- 实际飞书成员再次登录是验收步骤。测试中不输出 App Secret、用户访问令牌或完整 ID Token。

## 边界与风险

- Hydra 2.3 的后端通知是异步的，不能单独保证即时跨项目退出；受保护请求的撤销检查承担这一保证。若 SSO 或数据库暂时不可用，演示项目拒绝受保护请求。
- 已签发的离线令牌无法在无需查询的外部服务中被强制撤回；未来项目若需要同样的即时保证，必须校验撤销状态或采用等效的中央会话机制。
- 这仍是本机开发配置，Compose 中的固定密钥和密码不可直接用于线上。
